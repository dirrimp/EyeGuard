# EyeGuard Onn monitor: phase 2 (health only)

Design and conditions: `docs/ONN-SCREEN-MONITOR-REVIEW.md`. Database side: `supabase/onn_monitor_phase1.sql` (live).

**What this app does:** an accessibility service takes a screenshot every 15 s while the TV is on, looks at it in memory
(is it black? is it changing?) and discards it. Every 5 minutes it sends only **counts** to `eg_onn_heartbeat`: screenshots
attempted / succeeded / analysed, black frames, distinct frames, screen-on seconds, app version, its own signing-certificate
hash and whether the service is enabled. **No image, text or URL leaves the box in phase 2.**

**What it deliberately does not do:** no detection (phase 3), no web access (phase 4), no `WRITE_SECURE_SETTINGS`
(it never re-enables itself; a viewer switching it off is a *detection* case: the server emails after 3 minutes),
no self-update (manual ADB installs only), no logging of the token, no files written, one permission (INTERNET), one
server host (a constant in `Config.java`).

**Honest limits:** the counts come from the box, so a modified app could report anything: this is detection, not proof.
Protected (DRM) video comes back black and is reported as such. Not yet compiled or run on the real box (see the PR).

## Files
- `AndroidManifest.xml`, `res/`: one service, INTERNET only, `canTakeScreenshot`, no window content.
- `src/com/eyeguard/onn/`: `GuardService` (loop), `FrameStats` (counts), `Heartbeat` (JSON + HTTPS), `Config` (credentials file).
- `build.sh`: unsigned APK from raw SDK tools in Agent IT's network-less, hash-pinned container. No keystore is ever there.

## Device config (pushed over ADB at install; never committed)
`/sdcard/Android/data/com.eyeguard.onn/files/onn-config.json`: `{"token":"<64 hex>","anon_key":"<publishable key>"}`.
The token is generated by Jonah; Dad's database holds only its SHA-256. The anon (publishable) key is the same public key the dashboard uses.

## Build, sign, install (Jonah present for the last two)
1. Agent IT builds `onn-guard-unsigned.apk` (`build.sh`) from a pinned commit and records its sha256.
2. Jonah signs it on his Mac with `apksigner` (key and passphrase never leave the Mac): see Agent IT's runbook.
3. Dad approves the build in the database (version + certificate sha256 `9ec032db…0162`).
4. ADB session (Agent IT's runbook): temporary firewall rule, install, push the config, enable the service with `settings put secure`, tests, close out.
