# EyeGuard Onn monitor (phase 3, version 0.2.1: health + on-box exposure detection)

Design and conditions: `docs/ONN-SCREEN-MONITOR-REVIEW.md` (#162), `docs/ONN-PHASE3-DETECTION-DESIGN.md` (#166). Database side:
`supabase/onn_monitor_phase1.sql` and `onn_monitor_phase3.sql` (both live).

**What it does.** An accessibility service takes a screenshot every 15 s while the TV is on and examines it in memory: black? changing?
and **does it show explicit exposure?** The detector is the Mac's NudeNet 320n model, bundled in the APK and checked against its pinned hash,
run with ONNX Runtime on 2 threads, with the Mac's own post-processing and 0.80 threshold (`Postprocess`). The frame is then discarded.
Only when a frame is flagged is a picture kept, for as long as it takes to: scale it to at most 1280 wide, **blur it like the Mac's RED frames**
(`Blur`, radius width/75), JPEG-encode the blurred pixels (quality 80), **encrypt it** for Dad's offline key and the approved browser keys
(`Egf2`, `Recipients`), upload the ciphertext, and record the flag through `eg_onn_flag`. Every 5 minutes it sends counts and the detector's
self-test numbers to `eg_onn_heartbeat`; **the server** decides whether the detector is healthy (it compares the numbers with the Mac's).

**What it deliberately does not do.** No suggestive tier (the Mac's CLIP pass does not fit this box): exposure only. No web access (phase 4),
no `WRITE_SECURE_SETTINGS` (it never re-enables itself), no self-update (manual ADB installs), no logging of anything, no files written, one
permission (INTERNET), one server host (a constant in `Config.java`). Un-blurred pixels never leave the method that blurs them; the upload queue
holds ciphertext only, in memory, at most 10 items and 12 minutes.

**End-to-end self-test.** An empty file named `selftest-flag`, pushed over ADB into the app's folder during an install session, makes the service send ONE
synthetic test flag (label `ONN_TEST`: a yellow dashboard row, no email) through the whole blur, encrypt, upload and record path. The picture is drawn in code
(`TestFrame`), never a screenshot. Needs `supabase/onn_monitor_phase3b.sql`.

**Telemetry.** ONNX Runtime's Android package registers a telemetry ContentProvider. This app never merges that manifest, the build **removes the
13 telemetry classes** from the library jar and **fails** if any trace is left in the result, and the detector also sets `ORT_DISABLE_TELEMETRY`
and calls `setTelemetry(false)`. The router's deny log would show any attempt.

**Honest limits.** The counts and the self-test numbers come from the box, so a modified app could report anything: detection, not proof.
DRM video comes back black and is reported as such. The detector's recall on this box's content is unmeasured.

## Files
- `src/com/eyeguard/onn/`: `GuardService` (loop), `Detector` (model + self-test), `Postprocess`, `FlagFrame` + `Blur`, `Egf2` + `Recipients`
  (generated by `tools/gen_onn_recipients.py`), `FlagName`, `FlagUploader`, `Heartbeat`, `FrameStats`, `Config`.
- `build-phase3.sh`: the unsigned APK from raw SDK tools in Agent IT's network-less, hash-pinned container (needs `/pins`: the pinned ONNX Runtime
  pieces and the model). `build.sh` is the legacy phase 2 (0.1.0) build and refuses to run.
- `test/`: plain-JVM tests (not in the APK): `Egf2Test`, `FramePrepTest`, `TitleFactsTest`.

## Device config (pushed over ADB at install; never committed)
`/sdcard/Android/data/com.eyeguard.onn/files/onn-config.json`: `{"token":"<64 hex>","anon_key":"<publishable key>"}`.

## Build, sign, install (Jonah present for the last two)
1. Agent IT builds `onn-guard-unsigned.apk` (`build-phase3.sh`) from a pinned commit and records its hashes (`BUILD-PHASE3.txt`).
2. Jonah signs it on his Mac (key never leaves the Mac), certificate sha256 `9ec032db...0162`.
3. **Dad approves the build in `onn_approved` INCLUDING its model hash, BEFORE it is installed** (see the commented insert in `onn_monitor_phase3.sql`),
   or the first heartbeat raises the "nobody approved" email.
4. ADB session (Agent IT's runbook): temporary firewall rule, install over 0.1.0 (`adb install -r --no-incremental`), push the config if needed,
   confirm the service is still enabled, tests, close out.
